03.Inside a production backend

Scope note: the platform below is under NDA, so this describes the engineering rather than the client or the product. It is one system, broken into the layers it is actually built from — and what I built inside each one.

L1

API layer

90+ REST endpoints across session auth, resource CRUD, async job triggers, a multi-stage review workflow, and a CORS-gated external feed. Role checks run in middleware before any handler; long jobs return 202 and are polled rather than held open; list endpoints page in bounded chunks. The same routers mount in-process for a one-container deploy or run standalone — one codebase, two topologies.

Express · TypeScript · REST · RBAC middleware
L2

Data layer

18+ forward-only Postgres migrations — never edited, only added to. One universal join key that every domain table hangs off, cascade deletes so orphan rows can’t exist, JSONB where the shape is still moving, and append-only audit tables that are inserted into but never updated. Business invariants live in the database as triggers and CHECK constraints, so no application bug can bypass them.

Postgres · SQL migrations · JSONB · triggers · indexing
L3

Concurrency & pipeline layer

Long-running workers poll a status column and claim a batch atomically (pending → processing) so two processes never take the same row — no external message broker needed. Every write has a natural key, so a retry is a no-op instead of a duplicate. Transient upstream failures back off exponentially; repeat offenders get parked in a cooldown map so the backlog keeps draining. A scheduled reconciliation sweep self-heals four separate fault modes and keeps the pipeline eventually consistent.

Async workers · atomic claim · idempotency keys · backoff · self-healing sweep
L4

AI integration layer

Speech-to-text and LLM scoring wired in as first-class pipeline stages rather than bolted on: large structured JSON responses validated on the way back, retry and backoff on rate limits and 5xx, and rubric versioning deliberately decoupled from the governance workflow so editorial changes never invalidate historical scores.

Speech-to-text · LLM grading · structured output · rubric versioning
L5

Security layer

HMAC-SHA256 signed session cookies with constant-time verification and no server-side session store, scrypt password hashing, role-gated routes, and row-level security enabled on every table with all writes flowing through a server-side service role — a documented trade-off that concentrates authorization in one auditable middleware layer while leaving the door open to per-role database policies later. Private media is served through short-lived signed URLs, and PII is stored only as a salted hash.

HMAC sessions · scrypt · RBAC · row-level security · signed URLs · PII hashing
L6

Deployment layer

One codebase, two shapes: a single container running the web tier plus every long-running worker, or an esbuild-bundled serverless function for the stateless web tier with the polling workers hosted separately — because polling loops and in-memory state don’t survive serverless timeouts. Health checks with a restart policy, 12-factor env config that fails fast on a missing variable, and a pinned runtime version.

Railway · Vercel · esbuild · health checks · 12-factor config
