How I turn lab data into models

Every point on a plot cost somebody a day in the lab. That is the difference between scientific data and the kind most models are trained on — it is expensive, there is never enough of it, and it arrives with an error bar attached. Each pillar below opens into the practices it covers; open any one of those for what it actually is.

01 Measurement & uncertainty a number without its error is a rumour
Error propagation

Carrying instrument and replicate error through every calculation, so the final figure arrives with a range rather than a false precision.

Replicates & controls

Running the same condition more than once, with a known control beside it, so a difference can be told apart from noise.

Detection limits

Knowing the value below which the instrument is reporting its own noise, and refusing to model anything underneath it.

Calibration curves

Relating instrument signal to real concentration through a fitted standard series, and re-running it when the instrument drifts.

Significant figures

Reporting only the digits the measurement supports. A model that returns six of them is not more accurate, only less honest.

02 Experimental data & provenance what the instrument actually gave you
Instrument exports

Getting data out of whatever format the instrument writes, without losing the metadata attached to it on the way.

Run & batch metadata

Recording which instrument, which operator, which day, which batch — because those are the confounders that surface later.

Unit normalisation

Putting everything into one unit system before anything is compared. A large share of scientific data bugs are unit bugs.

Outlier triage

Deciding whether a strange point is a failed measurement or a real result by going back to the run, not by reaching for a statistical rule.

Dataset versioning

Pinning the exact dataset behind a figure, so a result from six months ago can be reproduced rather than approximately recalled.

03 Molecular & materials representation turning matter into features
SMILES & molecular graphs

Representing a molecule as a string or a graph a model can read, canonicalised so the same molecule has exactly one form.

Molecular descriptors

Computed physicochemical properties — mass, logP, polar surface area, atom counts — as the tabular features a classical model needs.

Fingerprints

Encoding which substructures are present as a bit vector, which is what similarity search and most screening models actually run on.

Composition & structure features

For materials: stoichiometry, crystal structure and processing conditions turned into columns rather than left in the method section.

Standardisation

Salts stripped, tautomers and charge states resolved, so two records of one compound do not enter the dataset as two compounds.

04 Feature engineering from chemistry domain knowledge as columns
Physically meaningful features

Building the features the underlying chemistry says should matter, rather than throwing every computable descriptor at the model and hoping.

Derived rates & slopes

Turning a time series into the quantity that carries the signal — a capacity fade slope, a rate constant, a degradation rate.

Condition encoding

Temperature, C-rate, pH, pressure and solvent captured as features, because a result only means anything alongside the conditions that produced it.

Correlated feature pruning

Removing descriptors that measure the same thing, so importance stays readable and the model is not counting one property five times.

05 Validation for scientific data splits that don’t lie
Scaffold & cluster splits

Splitting by molecular scaffold or material family rather than at random, so the test set is genuinely new chemistry instead of near-duplicates.

Grouped splits

Keeping every measurement from one batch, cell or plate on the same side of the split, so a batch effect cannot leak the answer across.

Temporal splits

Training on earlier experiments and testing on later ones, because that is the order in which the model will actually be used.

Applicability domain

Stating where the model is allowed to be trusted, and having it decline rather than extrapolate outside the chemistry it was shown.

Uncertainty on predictions

Every prediction carrying a confidence, so a screening list can be ordered by expected value rather than by point estimate alone.

06 Modelling & screening from dataset to a shortlist
Baselines from chemistry

A physical or rule-based estimate first, because a model that cannot beat a known correlation has not added anything yet.

Property prediction

Regression or classification on a measured property — solubility, capacity, activity — with the error bar carried through to the output.

Virtual screening

Ranking a large candidate library so the lab tests the top of a list instead of a random slice of it.

Small-data methods

Techniques that work at a few hundred points, because that is what a real lab produces — regularisation, priors, and transfer from related tasks.

Interpretability

Being able to point at which descriptors drove a prediction, so a chemist can agree with it or argue with it.

07 Active learning & experiment design which experiment to run next
Acquisition strategy

Choosing the next experiments by expected information gain rather than by best predicted value, so the model keeps learning instead of confirming itself.

Exploration vs exploitation

Balancing candidates that look good against candidates the model is unsure about — deliberately, with a stated ratio, not by accident.

Design of experiments

Varying conditions on a designed grid instead of one factor at a time, so interactions become visible within the same number of runs.

Closing the loop

Feeding measured results back as labelled data, so every round of experiments makes the next round of predictions better.

08 Reproducibility & reporting a result somebody else can get
Notebook to pipeline

Moving analysis out of an ad-hoc notebook into a script that runs the same way twice, in the same order, from the same inputs.

Pinned environments

Fixed dependency versions and fixed seeds, so a rerun produces the same numbers on a different machine a year later.

Figures from code

Every plot regenerated from the data by a script, so a figure and the numbers behind it cannot quietly drift apart.

Reporting negatives

Recording what did not work. In R&D that is half the information, and it is almost never written down.

Audit trail

Who changed what and when, so a result that ends up in a decision can be traced back to the run that produced it.

Read this as the standard, not the résumé: it is the list I hold scientific work to. Large-scale quantum chemistry, automated high-throughput experimentation, and GLP or GMP-regulated pipelines I have not run — I know the shapes and the trade-offs, and I would rather say so plainly than claim scars I do not have.

01 Battery materials cells, cycling and degradation
  • Cell chemistry
  • Electrolytes
  • Degradation
  • Cycling data

What I add Cycling, impedance and degradation data arrives noisy and split across instruments. I turn it into a versioned dataset and build capacity and lifetime models that carry their own uncertainty, so the cell team gets a range rather than a single confident number.

02 Hydrogen systems production, storage, catalysis
  • Production
  • Storage
  • Catalysis

What I add Catalyst and storage screening produces far more candidates than any lab can test. The useful work is the ranking model and the pipeline around it, so the next dozen experiments are chosen rather than guessed.

03 Drug discovery molecules to properties
  • Cheminformatics
  • Property prediction
  • Virtual screening
  • Assay data

What I add Assay data is messy, batch-effected and regulated. I build the pipeline with a real audit trail — append-only logs, versioned datasets, reproducible runs — so a property-prediction model can survive a review rather than only a demo.

04 Scientific data engineering the invisible pipeline
  • Ingestion
  • Cleaning
  • Versioning
  • Pipelines

What I add Lab data ingestion, cleaning and versioning: the unglamorous layer that turns hard-won measurements into a dataset somebody else can trust and rerun.

05 Statistics & uncertainty error as a first-class citizen
  • Error propagation
  • Experimental design
  • Confidence intervals
  • Significance

What I add Error, noise and confidence are first-class in a lab notebook, and they should be in a model report too. This is the habit chemistry teaches that most engineering never does.
